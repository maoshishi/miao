# 咪了个喵 🐱

一个「三张一样就消除」的猫咪小游戏，手机浏览器直接玩，可以放到 GitHub Pages 上发给朋友。
纯静态页面，不需要装环境、不需要编译。

---

## 一、怎么玩

1. 点桌面上的一张卡牌，它会跳进下面的**猫窝**。
2. 猫窝里凑齐 **3 张一样的猫** 就自动消掉。
3. 猫窝只有 **7 个位子**，满了就「猫窝已满」。
4. 被压住（颜色发暗）的牌点不动，要先拿走上面的。
5. 每局开局送 **移出 / 撤回 / 洗牌 各 1 个**：
   - **移出**：把猫窝最前面 3 张**放回牌桌原位**，还能再点（不会凭空消失，所以不会卡死）。
   - **撤回**：把最后放进猫窝的那张退回原位。
   - **洗牌**：桌面上的牌重新分配图案。
6. 猫窝满了会弹出**成语接龙**：自己把下一句**写进输入框**，接得上（是成语、首字对）→ 猫窝清出 3 个位子 + 额外送 1 个「移出」；写错不要紧，会**立刻换一句**让你接着接。**每局只能复活一次**，放弃或关掉就是本局结束。
7. **玩到一半关掉浏览器也不会丢**：牌面、猫窝里的牌、道具数量都会自动存在手机里，下次打开直接接着这一局玩。死了或者通关了就不存档，下次打开是全新的一局；想主动重来，用「设置 → 重开本局 / 从第 1 局重新开始」。

## 二、本地预览

方式一（最简单）：直接双击 `index.html`。

方式二（推荐，手机同 WiFi 下也能看）：

```powershell
cd "E:\小小\咪了个喵"
python tools/devserver.py 8124
```

然后浏览器打开 `http://localhost:8124/index.html`。
手机想看就把 `localhost` 换成电脑的局域网 IP（例如 `192.168.1.8:8124`）。

> `tools/preview-phone.html` 是一个 390×844 的手机外壳预览页，调样式时用。

## 三、部署到 GitHub Pages

1. 在 GitHub 新建一个仓库，比如 `miao`（**不要**勾选 Add README）。
2. 把整个文件夹上传：
   - 网页版：仓库页 → `Add file` → `Upload files` → 把 `index.html`、`css/`、`js/`、`picture/`、`icon-192.png`、`icon-512.png`、`manifest.webmanifest`、`sw.js`、`.nojekyll` 全部拖进去 → Commit。
     （`picture/` 里只需要 `cards/`、`bg.jpg`、`nest.png`；那些原始大图不参与运行，可以不传，省流量。）
   - 或者用命令行：
     ```bash
     cd "E:\小小\咪了个喵"
     git init
     git add .
     git commit -m "咪了个喵 第一版"
     git branch -M main
     git remote add origin https://github.com/你的用户名/miao.git
     git push -u origin main
     ```
3. 仓库 → `Settings` → 左侧 `Pages`：
   - Source 选 **Deploy from a branch**
   - Branch 选 **main**，目录选 **/ (root)** → Save
4. 等 1 分钟，地址是：

   ```
   https://你的用户名.github.io/miao/
   ```

5. 手机打开这个地址就能玩；Safari / Chrome 里选「添加到主屏幕」就变成 App 图标，断网也能玩。

> 注意：`.nojekyll` 这个空文件别删，它让 GitHub 不要用 Jekyll 处理文件。
> 仓库名如果是 `用户名.github.io`，地址就是 `https://用户名.github.io/` 根目录。

### 更新版本后手机上还是旧的？

`sw.js` 里有离线缓存。改完游戏文件后，把第一行 `var V = 'mlm-v7';` 改成 `mlm-v8`（下次 `v9`…）再上传，用户刷新两次就能拿到新版。

## 四、卡面素材

### 现在的状态

已经处理好 **17 种卡牌**：

- **11 种猫**：橘猫、三花猫、狸花猫、奶牛猫、黑猫、白猫、英短蓝猫、布偶猫、暹罗猫、银渐层、玄猫
- **6 种玩具**：猫包、猫砂铲、猫粮、玩具鼠、逗猫棒、鱼骨头

牌桌背景（`picture/bg.jpg`）和猫窝木框（`picture/nest.png`，已抠成透明）也是脚本从原图生成的。

### 图片怎么来的

原始文件都留在 `picture/` 里，脚本 `tools/prepare-cards.py` 负责：

| 输出 | 说明 |
| --- | --- |
| `picture/cards/01.png` ~ `17.png` | 卡面：裁掉底部中文名 / 右上角红印章 → 裁到内容框 → 居中放进 400×400 奶油底 `#FFF9ED` |
| `picture/bg.jpg` | 牌桌背景（`牌桌背景2.jpg`，奶油色猫爪花纹），压到 900px 宽、JPEG 质量 84 |
| `picture/nest.png` | 猫窝木框，抠掉外面的白底，保留透明通道 |

### 想换图 / 加新卡

1. 把新图丢进 `picture/`。
2. 打开 `tools/prepare-cards.py`，在 `CARDS` 表里加一行：

   ```python
   (18, '新文件.png', '名字', False),   # 编号, 文件名, 显示名, 底部是否带中文名
   ```

   第 4 个参数：图片底部有「中文名字」就写 `True`（会自动裁掉），玩具那种没有文字的写 `False`。

3. 运行（或双击 `tools/prepare-images.bat`）：

   ```powershell
   python tools/prepare-cards.py
   ```

4. 把 `js/config.js` 里的 `MAX_TYPES` 改成新总数，并在 `CATS` 里补上名字和占位色。

### 规则

- 编号 `01` ~ `17`，**必须是两位数补零**。
- 缺图不会崩：会显示成带名字的彩色方块（设置里能看到 `卡牌素材 x/17`）。
- 卡面底色是 `#FFF9ED`，和网页里 `--cream` 一致，所以贴到卡上无色差。
- 依赖 `pillow` 和 `numpy`：`pip install pillow numpy`。

## 五、难度怎么调

改 `js/config.js` 里的 `LEVELS`，一局一行。牌的大小、牌桌的「设计尺寸」是全游戏统一的，难度靠**叠层数 + 种类数 + 顶层铺多密**来调。

| 字段 | 意思 |
| --- | --- |
| `types` | 本局用几种卡牌（最多 17 种，从已加载的图片里随机挑） |
| `layers` | 中间那坨叠几层 |
| `cols` / `rows` | 中间那坨几列几行 |
| `stagger` | 奇数层错开多少（`0.5` = 错半张，最经典） |
| `sideStacks` / `stackSize` | 四角的扇形牌堆：几摞、每摞几张 |
| `sideCards` | 两侧中间竖排的散牌（每边几张） |
| `sparseTop` | 最上面那层只铺一部分格子（亮牌散在暗牌上） |
| `sparseFill` | 顶层铺 5 分之几：`2` = 2/5（最稀、最难看清），`4` = 4/5 |
| `cellGap` / `stackStep` / `rowStacks` | 简单局（图一那种 3×3）用：格子间距、每张错开多少、每行叠几张 |
| `idiom` | 复活题难度：`easy` / `hard` / `expert` |
| `diff` | 顶部显示的文字 |

现在的配置：

| 局数 | 难度 | 牌数 | 种类 | 结构 | 能直接点的牌 |
| --- | --- | --- | --- | --- | --- |
| 第 1 局 | 简单 | 18 | 6 | 图一那种 3×3 格：上面一行每格叠 3 张、中间 2 张、下面 1 张 | 9 |
| 第 2 局 | 中等 | 96 | 9 | 5×7 密堆 3 层（两层实心 + 稀疏顶层）+ 四角牌堆 + 两侧散牌 | 26 |
| 第 3 局起 | 地狱 | **336** | **15** | 5×7 密堆 **9 层**（八层实心 + 稀疏顶层）+ 四角牌堆 + 两侧散牌 | 34 |

简单局就是图一那种摆法：3 列 3 行、格子之间有缝，后面那张往上露一条边（灰的、点不动），最前面那张才是亮的。整坨居中，上下留一大片空白。

中等/地狱局牌桌范围固定：中间 5 列 × 7 行，左右各一列（上下各一摞扇形牌堆、中间几张散牌）。牌面**所有局一样大**：手机 390px 宽时约 50px；上下各留 ~70px 空白，不会顶到屏幕边。

`config.js` 里的 `UNIT_W` / `UNIT_H` 就是牌桌的「设计尺寸」（单位是一张牌宽）。牌的大小 = `min(可用宽 / UNIT_W, 可用高 / UNIT_H)`，跟本局有多少张牌无关 —— 想整体放大/缩小所有局的牌，改这两个数就行。

每一层的错位方向会循环（右 → 下 → 右下），所以下层的牌总会露出半边，不会出现「上面一张把下面整张盖死」的情况；最顶上那层故意只铺一部分格子，压住下面 4 张，于是底下几层变成暗色，只有散落的亮牌能点。

关卡是**程序生成**的，每次开局都不一样，但生成时先随机出一条「可行的掀牌顺序」，再按每 3 张一组分配图案，所以**保证有解**。336 张牌的生成 + 求解顺序计算只要几毫秒。

想验证改动有没有破坏规则，跑一下自检：

```powershell
node tools/selftest.js
```

它会检查关卡结构、模拟通关、道具规则和成语题库。

## 六、成语题库

`js/idioms.js` 里三个难度，每条都是「上句 → 下句」的接龙对：

```js
['水落石出', '出人头地']   // 下一句首字必须是「出」
```

- `easy` 81 条、`hard` 81 条、`expert` 86 条。
- 复活时玩家**自己输入**下一句，判断规则：去掉空格和标点后——
  1. 和标准答案一字不差 → 算对；
  2. 或者是**词典里的四字成语**、而且**首字等于上一句的末字** → 也算对。

  也就是说「一鸣惊人 → 人山人海 / 人定胜天 / 人云亦云…」都行，不用猜题库里那一句。
- 词典在 `js/idiom-dict.js`，约 1 万条四字成语（由 `tools/build-idiom-dict.py` 从几个公开成语库合并生成）。
  只收录了**题库里出现过的接龙首字**开头的成语，体积才压得住；**加了新题之后重新生成一次**就能覆盖新首字：
  ```powershell
  python tools/build-idiom-dict.py --src D:\你的语料文件夹
  ```
- 写错 → 立刻换一道新题，可以让玩家一直试到接上为止；错 3 次后会提示新题的第 2 个字。
- 想加题就往对应数组里加，注意**下一句的第一个字必须和上一句的最后一个字相同**，而且**四个字**（提示里会显示字数）。

## 七、文件都是干什么的

```
index.html              页面骨架
css/style.css           全部样式（牌桌背景、猫窝木框、道具按钮、答题弹窗）
js/config.js            卡牌名单、关卡难度、道具数量 —— 常改的都在这里
js/engine.js            关卡生成 + 游戏规则（纯逻辑，不碰 DOM）
js/idioms.js            成语题库
js/idiom-dict.js        成语词典（判断玩家写的成语成不成立，脚本生成）
js/ui.js                渲染、动画、弹窗、答题流程、存档读档
picture/bg.jpg          牌桌背景（脚本生成）
picture/nest.png        猫窝木框（脚本抠好的透明 PNG）
picture/cards/01..17.png  处理好的卡面
picture/*.jpg|png       原始素材（不参与运行，留着方便重新处理）
tools/prepare-cards.py  素材批量处理（卡面 / 背景 / 木框）
tools/build-idiom-dict.py  重新生成成语词典
tools/prepare-images.bat  双击入口
tools/devserver.py      本地预览服务器（禁用缓存）
tools/preview-phone.html  手机外壳预览页
tools/selftest.js       自检脚本
manifest.webmanifest    加到主屏幕用的配置
sw.js                   离线缓存
```

**存档在哪儿：** 存在浏览器的 `localStorage`（键名 `mlm.save`），内容是整局快照：每张牌的图案 / 坐标 / 层号 / 状态、猫窝里的顺序、道具数量，地狱局约 12KB。点一次存一次太费，所以攒 350ms 写一次，切后台或关页面时立刻写。`js/ui.js` 里的 `SAVE_V` 是存档版本号 —— 以后如果改了摆牌规则、想让老存档作废，把它 +1 就行。
